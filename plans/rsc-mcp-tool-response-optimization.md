# RSC：模型响应压缩、批量读取与扩大分页

计划路径：`plans/rsc-mcp-tool-response-optimization.md`。

## 目标

减少 parser、reviewer 为读取 RFC 和模型而产生的工具往返，保留全部协议信息、来源证据、阅读记录和阶段 gate。

仅修改 RSC 的 MCP 响应与读取接口。最终 `protocol.json`、协议 schema、provider 选择和核验规则不变；不引入服务端并行执行或批量完成报告。

## 工具改造

### 模型响应压缩

- `query_model` 增加 `format="compact" | "records"`，默认 `compact`；`records` 返回现有记录结构，供调试和对照。
- compact 按对象类型及字段集合分组，以 `columns + rows` 表达记录，字段名只出现一次。
- 保留原始 record ID、step ID、全部字段、条件和证据引用。嵌套字段保持原有 JSON 结构。
- 重复证据定位集中保存为本页字典，记录通过索引引用；每页独立可读，不依赖此前调用的缓存。
- 使用紧凑 JSON。不得自动摘要条件、删除空值或合并不同协议概念。
- 提供统一解码函数，保证 compact 解码后与原始记录完全一致。阅读 gate 按实际交付的记录 ID 更新，两种格式等价。

### 批量读取 RFC

新增：

```text
read_batches(batch_ids, max_tokens=24000)
```

- 按任务分配顺序读取多个完整批次，返回正文、每批独立 receipt、已交付批次和剩余批次。
- 达到预算时只返回能够完整容纳的前缀批次，不截断正文，不为未交付批次生成 receipt。
- 首个批次无法容纳时返回明确错误及所需预算。
- 保留 `read_batch`，内部复用同一读取实现。
- 报告提交仍逐批执行，保持原有顺序和凭据校验。

### 扩大分页

- `query_model`、`get_changes`、`list_batches`、`list_findings`、`search_source` 增加 `max_tokens`。
- 默认预算 **24,000 tokens**，硬上限 **30,000 tokens**；允许调用方请求更小预算。
- 取消固定每页 50 条限制，按最终序列化响应的 token 数装入完整记录。
- 保留 `next_cursor`；分页响应携带当前 revision。模型相关后续分页须提交该 revision，版本变化时明确报错并要求重新读取。
- `get_changes` 保留全部 before/after 修改记录和 change ID，不将多次修改压缩为净变化。
- 单条记录无法容纳时明确报错，不静默丢弃字段或绕过阅读要求。

## 链路、审计与提示词

- 抽取公共分页、预算计算和响应编码组件，供工具与审计复用。
- 审计记录实际响应格式、预算、交付 ID、token 数和内容摘要，避免仅根据当前分页算法推测历史交付。
- 旧任务保持可查看、可审计；缺少新交付记录时使用原有审计路径。
- Codex 的工具输出额度覆盖新预算；Pi 扩展继续完整恢复超过默认截断长度的结果。恢复失败不得满足 gate。
- 更新 parser、reviewer 提示词：优先批量读取，完整遍历 cursor，理解 compact 字典与表格；不把摘要或关联引用视为已阅读原文。
- 记录每阶段读取调用次数、返回 tokens、重复读取量和耗时，为后续优化提供依据。

## 测试与验收

- compact 与 records 双向等价，覆盖嵌套字段、Unicode、引号、空值、重复证据和不同 step 字段结构。
- 超过 50 条短记录可在预算内一次返回；所有分页均可重建完整数据，无遗漏或重复。
- 批量读取覆盖预算边界、超大首批、非法顺序及重试；未交付内容不得获得 receipt。
- reviewer 漏读任一模型记录、diff 或必需批次时，gate 仍拒绝推进；版本变化不能混用分页。
- 验证超过 20 KB 的内容完整经过 Codex、Pi 适配链路，错误状态正确保留。
- 使用既有 Flash、Sol FTP 产物进行离线基准，报告压缩前后 tokens、页数、读取调用数和编码耗时；确认完整记录与证据一致。
- 运行完整 RSC 回归测试。真实模型耗时对比作为后续独立验收，不自动启动付费提取或 FTP 长跑。
